# How Do You Handle Competing Priorities?

**Approach:** [Scheduling from Acceptance Criteria](../personal-philosophies/scheduling-from-acceptance-criteria.md)

## Draft answer

> I handle competing priorities by defining the acceptance criteria for each outcome first: what must be true for the work to be successful? I then work backward from those outcomes to map dependencies, validation, and the actual time required. That makes it easier to distinguish a truly urgent task from a visible task that can wait.
>
> When two priorities still conflict, I use the project’s core values as the decision rule. On my current project, those values are security and stability, so I default to the more secure and stable option. The exception is when a dependency chain blocks that option. In that case, I make the conflict explicit and prioritize the prerequisite work that unblocks the path. I also review whether recurring operational work is consuming too much capacity; if it is, I treat reducing that toil as an engineering priority. The goal is not to do everything at once—it is to sequence work so the team makes durable progress toward the most important outcome.

## What the interviewer is listening for

- You make tradeoffs based on customer impact and business priorities.
- You communicate what will not happen, not only what will.
- You protect quality while delivering the highest-value work.

## Skim notes

- Define acceptance criteria.
- Work backward.
- Map dependencies.
- Prioritize security, stability.
- Unblock dependency chains.
- Review time allocation.
- Reduce recurring toil.

## Details to add before the interview

- What are the acceptance criteria for the competing outcomes?
- Which dependencies determine the viable sequence?
- Which project values should decide the tradeoff?
- What recurring work should become an engineering project?

## Likely follow-ups

- How do you communicate a tradeoff that delays an important request?
- When would you prioritize a smaller incremental improvement over a comprehensive solution?
- How do you tell whether operational work is consuming too much capacity?
